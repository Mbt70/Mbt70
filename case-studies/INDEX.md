## 문서 관리 기준

프로젝트가 바뀔 때 다음 내용을 함께 갱신합니다.

1. **문제와 역할** — 해결하려는 문제, 팀의 작업과 개인 기여를 구분합니다.
2. **실행 방법** — 필요한 환경, 실행 명령과 데모 링크를 적습니다.
3. **검증** — 실행한 검사·실험, 기준 커밋이나 날짜, 결과와 제한을 남깁니다.
4. **현재 상태** — 구현 완료, 개발 중, 계획을 구분합니다.
5. **다음 단계** — 우선순위가 높은 후속 작업을 이슈·PR에 연결합니다.

README의 대표 프로젝트, GitHub 고정 저장소, 포트폴리오, LinkedIn 설명은 같은 사실을 기준으로 맞춥니다. 목표 성능과 시뮬레이션, 실제 측정 결과를 구분하고, 수상·순위는 확인된 결과만 반영합니다.

공개 문서에는 비밀정보, 비공개 대화와 내부 자료를 포함하지 않습니다. 대회·팀 프로젝트의 공개 범위를 확인하고, 화면·로그는 필요한 내용만 공개합니다.
